# AI 编写项目注意事项与标准流程

## 注意事项

1. 先写清边界：目标用户、核心流程、非目标、验收标准。没有边界时不要生成代码。
2. 一次只做一个垂直模块。跨模块的大范围生成会放大误解，也让 review 难以定位问题。
3. 外部模型输出是不可信输入。必须定义 schema、严格校验、处理字段缺失和越界，再进入数据库或执行层。
4. 上传文件必须限制扩展名、大小和 MIME 类型，并使用服务端生成的存储路径，不能信任客户端文件名。
5. 长任务必须异步化。要有显式状态机、失败原因、幂等触发和用户可理解的重试路径。
6. 密钥只通过环境变量或专用密钥管理注入。日志、示例配置、测试快照中不得出现真实密钥。
7. 用户视频、模型响应缓存和渲染产物不属于源码，必须保存在被忽略的运行时目录。
8. 文档不是附属品。接口契约、架构图和 README 必须随实现同步，否则后续 AI 会基于过期上下续写。
9. 测试要覆盖负面路径：非法状态流转、坏输入、外部服务失败、渲染工具缺失。
10. 每个模块完成后必须 review。review 关注正确性、可恢复性、安全边界和无关联变更，而不是风格偏好。

## 标准流程

1. 需求确认：写下目标、非目标、用户流程和验收标准。
2. 设计：确定模块边界、接口契约、数据模型和状态机。
3. 骨架：创建工程结构、依赖清单、忽略规则和基础测试。
4. 实现：按模块顺序实现，每轮只解决一个模块。
5. 测试：先写覆盖当前行为的测试，再实现或同步补齐；负面用例必须有。
6. Review：按 checklist 独立审查代码，记录并修复问题。
7. 复测：修复后重跑当前模块测试和受影响的回归测试。
8. 文档：更新接口契约、架构说明和运行指南。
9. 提交：小粒度提交，提交信息描述行为而非文件清单。
10. 回归：阶段完成前运行完整测试、构建和端到端流程。

## 模块完成定义

一个模块只有在满足以下条件时才算完成：

- 核心路径可用，失败路径有明确反馈。
- 测试通过，且包含至少一个负面用例。
- review checklist 无未处理的 P0/P1 问题。
- 文档与实际接口一致。
- 运行时产物不会进入版本库。
